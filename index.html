案例背景

資料庫給誰用、要解決什麼問題

過去課程時間、選課名單和成績分別放在不同的試算表裡。一門課改了上課時間，要同時改好幾個檔案；學生選到衝堂的課，也只能靠系辦人工比對。這個資料庫把系所、教師、學生、課程、上課時段和選課紀錄放在一起，讓下面三種人都能用 SQL 直接得到答案。

學生
看自己的週課表；加退選時知道有沒有選到衝堂的課。
授課教師
看修課名單，比較每位學生和同班平均的差距。
系辦、註冊組、教務處
發通知要名單、統計老師開課數、檢查學分是否足夠、追蹤成績登錄進度。

資料庫設計

ERD、欄位說明與樣本資料

PK 主鍵：唯一識別一列FK 外來鍵：指向另一張表的主鍵箭頭：外來鍵 → 被參照的主鍵，旁邊標示 1 對 N

表與表的關係

  • department 1 : N student一個系有很多學生，每位學生只主修一個系。
  • department 1 : N teacher每位老師隸屬一個系所。
  • department 1 : N course每門課由一個系所開設。
  • teacher 1 : N course一門課由一位老師授課（本案例不處理合授）。
  • course 1 : N course_time一門課每週可以有好幾段上課時間。
  • student N : M course一個學生修很多課，一門課有很多學生，靠 enrollment 連起來。

為什麼這樣設計

  1. 上課時間獨立成 course_time資料結構一週上兩次（週二 2–3 節、週四第 2 節）。如果把時間塞進 course，就得開 time1、time2 欄位或存成一段文字，Q8 就沒辦法用 SQL 直接比較節次找衝堂。拆開後，一列就是一段時間。
  2. enrollment 用（學號, 課號）當主鍵學生和課程是多對多，必須用中間表連接。兩欄合起來當主鍵，保證同一位學生不會重複選同一門課。成績屬於「這一次選課」，所以放在這張表。
  3. score 允許 NULL還沒登分和考 0 分是兩回事。Q5 示範兩種算法的平均差多少。
  4. 系名只存一次student、teacher、course 都只存 dept_id，系名只在 department。系所改名只要改一列，不會出現同一系兩種寫法。
  5. 用 CHECK 擋掉不合理的值年級 1–4、星期 1–5、開始節次 ≤ 結束節次、成績 0–100。資料寫入時就會被擋下，不用等查詢時才發現。
